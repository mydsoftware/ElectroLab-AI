# معماری فنی ElectroLab AI

## هدف

ایجاد بستر توسعه‌پذیر برای شبیه‌سازی مدار، اجرای Firmware، تست سخت‌افزار واقعی و ثبت نتایج قابل تکرار.

## اصول معماری

- هسته مستقل از موتورهای شبیه‌سازی است.
- هر موتور از طریق Adapter جداگانه متصل می‌شود.
- اجرای تست فیزیکی فقط از طریق Hardware Agent مجاز و کنترل‌شده انجام می‌شود.
- داده شبیه‌سازی و داده اندازه‌گیری واقعی باید منبع و نوع متفاوت داشته باشند.
- نتیجه PASS فقط نسبت به سناریو و حدود پذیرش همان تست معتبر است.

## اجزای اصلی

1. Web UI: طراحی پروژه، مشاهده شماتیک و نمودارها.
2. Core API: مدیریت پروژه، نسخه‌ها، مجوزها و گردش کار.
3. Simulation Orchestrator: انتخاب و اجرای موتور مناسب.
4. Hardware Agent: ارتباط محلی با برد و تجهیزات آزمایش.
5. Test Engine: اجرای سناریو و ارزیابی قطعی داده‌ها.
6. Diagnosis Engine: تحلیل خطا با ترکیب قواعد مهندسی و AI.
7. Report Engine: تولید گزارش با ردیابی نسخه‌ها و نتایج.

## قرارداد آداپتور شبیه‌ساز

هر آداپتور باید شناسه موتور، نسخه، ورودی‌های لازم، محدودیت‌ها، وضعیت اجرا، خروجی ساختاریافته و خطاهای قابل تشخیص را گزارش کند.

## قرارداد تست

هر سناریو حداقل شامل شناسه، نام کمیت، مقدار مرجع، تلورانس، واحد، روش اخذ داده، منبع داده و نسخه تحت آزمون است.

## مراحل توسعه

- مرحله ۱: API و مدل‌های پایه
- مرحله ۲: ذخیره‌سازی PostgreSQL و مدیریت پروژه
- مرحله ۳: آداپتور ngspice و مدیریت فایل مدار
- مرحله ۴: مدیریت Firmware و آداپتورهای MCU
- مرحله ۵: Hardware Agent فقط خواندنی و کشف تجهیزات
- مرحله ۶: کنترل ایمن تجهیزات با interlock و محدودیت‌های سخت‌افزاری
- مرحله ۷: گزارش و تشخیص خطا

## ایمنی

هیچ تست ولتاژ/جریان خطرناک نباید صرفاً با فرمان نرم‌افزاری قابل اجرا باشد. محدودیت جریان، فیوز، ایزولاسیون، توقف اضطراری و تأیید اپراتور باید در طراحی ایستگاه سخت‌افزاری لحاظ شوند.
